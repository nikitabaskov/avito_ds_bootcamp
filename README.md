# Поиск услуг: генерация кандидатов

Решение тестового задания Avito DS Bootcamp. Для каждого запроса выбираются 50 объявлений из заданного корпуса. Метрика — **macro Recall@50**: доля найденных релевантных объявлений, усреднённая по запросам.

**Платформа: 0,915389**, отправка №5, `EXP-022/core_s42`. Локальный dev: **0,914666**, полнота пула: **0,977820**. Настройки — [configs/final.json](configs/final.json), история экспериментов — [DEVELOPMENT_LOG.md](DEVELOPMENT_LOG.md).

## Данные и признаки

Использованы только данные задания:

| Файл в `data/input/` | Содержание | Назначение |
| --- | --- | --- |
| `train.parquet` | 497 673 положительные пары запрос–объявление | Обучение, валидация, агрегаты истории |
| `benchmark_items.parquet` | 189 212 объявлений | Корпус итогового поиска |
| `benchmark_queries.parquet` | 2 452 запроса без разметки | Итоговый инференс |

Основной сигнал — текст запроса и фильтров, заголовок, параметры и описание объявления: **90,41% ID объявлений benchmark отсутствуют в train**. География учитывается списками кандидатов и признаками; жёсткий фильтр по локации теряет релевантные объявления. Подробности — в [EDA](notebooks/eda.ipynb).

Ранжировщик использует **52 признака**:

- ранги и оценки BM25/E5, RRF, число поисковых списков кандидата;
- косинусная близость, пересечение слов заголовка и параметров;
- совпадение локации и категории, расстояние до центра, размер локального корпуса;
- цена, рейтинг, отзывы, доступность связи, длины полей, признаки запроса и пустых фильтров;
- резервный центр и переходы между локациями по train-истории, признаки ненадёжной географии;
- распределение микрокатегорий по 40 близким историческим запросам;
- близость к среднему вектору объявлений, выбранных по соседним запросам;
- косинус и ранг второго энкодера `deepvk/USER-base`.

`query_id` и `item_id` служат ключами данных и не передаются модели как признаки. Специальных ответов для отдельных запросов нет.

## Алгоритм

1. **BM25** со Snowball-стеммингом русского языка. Заголовок повторяется трижды, затем добавляются параметры и описание; фильтры включены в запрос.
2. **Дообученный multilingual-e5-base**: префиксы `query:` и `passage:`, нормализованные векторы. Документ содержит заголовок, первые 500 символов параметров и описание; предел — 512 токенов.
3. Каждый канал возвращает global top-400, top-300 своей локации и top-50 в радиусе 25 км. Объединение через RRF (`k=60`) даёт в среднем 978 кандидатов на dev.
4. **CatBoostRanker** выбирает top-50: `YetiRank`, 500 деревьев, глубина 6, learning rate 0,05, seed 42, CPU, без ранней остановки.

E5 дообучался одну эпоху на 79 576 тройках с трудными отрицательными примерами. Из дообучения исключены 6 000 текстов выборки ранжировщика. Из negatives исключены известные позитивы того же текста; в батче не повторяются запросы и объявления. USER-base используется для признаков, отдельного списка кандидатов не создаёт.

## Валидация и ошибки

Split 80/10/10 построен по SHA-256 нормализованного текста с seed 42: один текст не попадает в разные части. Dev содержит 2 452 текста, по одному контексту на текст; позитивы контекста дедуплицированы. Исторические признаки train считаются cross-fit по пяти группам текстов; dev и внутренний validation исключены из обучающей истории. Для benchmark используется вся train-история.

Отдельно измерялись полнота пула и итоговый Recall@50. Разности проверялись парным bootstrap по запросам, 5 000 повторов, спорные изменения — на seed 42/43/44 и срезах по географии, фильтрам и длине запроса. Интервалы не учитывают множественный подбор по dev.

Holdout test в подборе не участвовал и открыт один раз для зафиксированной конфигурации: **0,907613** при полноте пула 0,973899. Против dev это −0,71 п.п. при непарном bootstrap [−2,28; +0,88] — в пределах шума, систематического смещения dev не видно.

| Оценка | Recall@50 | Корпус |
| --- | ---: | --- |
| Dev | 0,914666 | 344 825 объявлений, 2 452 запроса |
| Holdout test | 0,907613 | тот же корпус, другие 2 452 запроса |
| Платформа | **0,915389** | 189 212 объявлений benchmark, 2 452 запроса |

Три оценки укладываются в диапазон 0,8 п.п. Локальные части и benchmark различаются корпусом и распределением запросов, поэтому числа не взаимозаменяемы, но расхождение между ними меньше, чем разброс между вариантами решения. Разбор по срезам — в [журнале](DEVELOPMENT_LOG.md).

| Ошибка | Что изменено |
| --- | --- |
| Нет объявлений своей локации, центр неизвестен | Резервный центр из истории, радиусный поиск, переходы между локациями |
| Позитив найден одним каналом, но проигрывает RRF | CatBoost получает ранги и оценки каналов отдельно |
| Синонимы и короткие неоднозначные запросы | Дообученный E5, микрокатегории соседей, признаки USER-base |
| Позитив есть в пуле, но не попал в top-50 | Совместно добавлены переходы, близость к выбранным объявлениям соседей и признаки ненадёжного центра |
| Расширение пула ухудшает отбор | Сохранён пул 400+300+50; широкий географический поиск отклонён |
| Рост dev не переносится на платформу | Глубина 8 и 1000 деревьев отклонены; итог — 6×500 |

У финальной модели потери поиска — **2,22 п.п.**, потери отбора — **6,32 п.п.** Разметка поведенческая: отсутствие выбора не доказывает нерелевантность. Dev и benchmark различаются корпусом и распределением запросов; локальная метрика служит для сравнения вариантов.

## Запуск

Команды выполняются из корня репозитория. Окружение: Python 3.12, `uv`, Linux. Версии зависимостей закреплены в `uv.lock`.

```bash
uv sync --locked
```

Поместите три исходных parquet-файла в `data/input/`. **Данные, обученные веса, эмбеддинги и кэши не входят в Git.** Для точного повторения отправки нужны исходные артефакты. Исходники позволяют повторить обучение, но побайтное совпадение после него не проверено и не гарантируется.

### Из готовых артефактов

Нужны исходный CatBoost `data/artifacts/experiments/EXP-022/core_s42/model.cbm`, дообученный E5 в `data/artifacts/models/e5ft/`, корпус `data/artifacts/split/corpus.parquet` и локальные веса USER-base. Эмбеддинги (`embeddings.npy` и `meta.json`) должны находиться в:

```text
data/artifacts/embeddings/split_e5ft_len512_p500/
data/artifacts/embeddings/benchmark_e5ft_len512_p500/
data/artifacts/embeddings/benchmark_USER-base_len512_p500/
```

Для повторения проверенного запуска также использованы исходные кэши `data/artifacts/runs/benchmark/` и `data/artifacts/runs/history/`.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
  uv run --locked python -m candgen --output answer.csv
```

Результат — CSV с колонками `query_id,answer`, ID объявлений разделены пробелами. Рядом записывается `answer.meta.json` с хэшами и временем выполнения. Существующий CSV не перезаписывается. Проверяются входные файлы, веса CatBoost, формат ответа, принадлежность ID корпусу, дубликаты и SHA-256:

```text
c04e5d3f0e8311fa225a6bb9f33af877bb4da6f4fa4a2bdb7c8a01262e3876f3
```

Хэш воспроизведён до и после рефакторинга на исходных артефактах. Пересчёт эмбеддингов и другое устройство могут изменить округление и порядок близких кандидатов; несовпадение завершает команду с ошибкой. Во время обучения и инференса веса загружаются только локально, внешние API не используются.

### Повторное обучение

Первичная установка зависимостей и скачивание открытых весов требуют сети; выполняются до офлайн-запуска:

```bash
uv run --locked hf download intfloat/multilingual-e5-base \
  --revision d128750597153bb5987e10b1c3493a34e5a4502a
uv run --locked hf download deepvk/USER-base \
  --revision e8446472f6024df155a04b2f0911b6044cabc51f
```

В новом рабочем каталоге, без кэшей от других весов:

```bash
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1

uv run --locked python -m candgen.workflows.prepare_split
uv run --locked python -m candgen.workflows.embed_corpus --corpus split
uv run --locked python -m candgen.workflows.finetune_dense --tag e5ft

uv run --locked python -m candgen.workflows.embed_corpus \
  --corpus split --model data/artifacts/models/e5ft
uv run --locked python -m candgen.workflows.embed_corpus \
  --corpus benchmark --model data/artifacts/models/e5ft
uv run --locked python -m candgen.workflows.embed_corpus \
  --corpus split --model deepvk/USER-base
uv run --locked python -m candgen.workflows.embed_corpus \
  --corpus benchmark --model deepvk/USER-base

uv run --locked python -m candgen.workflows.train --name retrained
uv run --locked python -m candgen \
  --model data/artifacts/experiments/retrained/model.cbm --output answer_retrained.csv
```

`--model` включает режим повторно обученной модели: проверяется контракт признаков и настроек, совпадение хэша отправки записывается в метаданные, но не требуется. При обучении сохраняются модель, настройки, dev-метрики, важности признаков и примеры ошибок. Для оценки готовой модели на dev:

```bash
uv run --locked python -m candgen.workflows.train \
  --name dev_check --model data/artifacts/experiments/EXP-022/core_s42/model.cbm
```

Исходные замеры: дообучение E5 — около 49 минут и 5,9 ГиБ GPU-памяти; обучение CatBoost — около 74 минут и 10,3 ГиБ RAM процесса. Машина разработки — RTX 5070 Ti Laptop, 12 ГБ VRAM. Инференс с заполненными кэшами занимает десятки секунд; это не время первого запуска. CPU поддерживается, построение эмбеддингов и обучение будут значительно медленнее.

## Открытые модели и библиотеки

| Компонент | Источник | Использование |
