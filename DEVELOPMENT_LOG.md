# Журнал разработки

Каждая законченная фича или улучшение оформляется отдельным коммитом и одной записью в этом файле. 

## Правила

1. Выбрать одну проверяемую цель и следующий номер `DEV-NNN`.
2. Реализовать изменение и выполнить относящиеся к нему проверки.
3. В том же коммите добавить запись: цель, результат, затронутые файлы, проверки, ограничения и следующий шаг.
4. Включить номер записи в заголовок коммита. Например: `feat: DEV-002 add reproducible data EDA`.
5. Не включать чужие незавершённые изменения, исходные данные, секреты и большие модельные артефакты. Не записывать запланированные проверки как пройденные.

Номер связывает запись с коммитом без циклической зависимости от его хеша. Найти коммит: `git log --oneline --grep='DEV-002'`. Получить историю: `git log --oneline -- DEVELOPMENT_LOG.md`.

Исходная точка: `fccd943` (`init commit`). Старые изменения задним числом на фичи не разделялись.

## DEV-002 — Jupyter EDA

- Цель: исследовать исходные данные до реализации поиска, сделать аномалии и закономерности понятными и проверяемыми.
- Результат: `notebooks/eda.ipynb`; после разделов 2–10 — короткие выводы простым языком, в начале — описание роли трёх файлов.
- Объём: размеры и схема трёх Parquet; целостность ID; дубли пар; конфликты атрибутов; пересечение train/benchmark; сдвиг фильтров и категорий; доступность кандидатов по location_id; границы Recall@50 при фильтрации; частоты и длины запросов; пропуски, цены, рейтинги, отзывы, координаты; длины и дубли текстов; буквальные совпадения; выводы для будущего поиска.
- Данные: train — 497 673 положительные пары «запрос — выбранное объявление» (обучение и локальная проверка); benchmark_queries — 2 452 запроса без ответов; benchmark_items — 189 212 объявлений, корпус финального поиска.
- Основные находки:
  - Новизна: 90,41% объявлений benchmark имеют новые ID; 63% текстов запросов новые; полный контекст запроса совпадает с train только у 4,4%.
  - География: у 427 из 2 452 запросов нет объявлений с тем же location_id; жёсткое равенство location_id ограничивает macro Recall@50 на известных train-позитивах уровнем 0,8040. Несовпадение кодов не доказывает другой физический город: геоиерархия неизвестна.
  - Сдвиг контекста: пустые фильтры — 33% строк train против 63% benchmark; категория 0 — 0,01% против 9,05%. 99% корпуса в категории 114.
  - Запросы: медиана 3 слова, p90 — 5; 100 частых текстов дают 25% строк train; 27 478 текстов встречаются в нескольких location_id. Позитивов на контекст: медиана 1, максимум 278.
  - Буквальные совпадения (20 000 пар): все слова запроса есть в полном тексте объявления в 67,6%, ни одного общего слова — в 7,1%; по заголовку — 36,5% и 28,4%.
  - Тексты: описание в медиане 1 054 символа, у 24% benchmark длиннее 2 000; параметры достигают 19 068 символов; 71 193 объявления benchmark повторяют чужой заголовок.
  - Числа: отрицательные цены всегда равны −1 (8,06% benchmark), цены 0 и 1 условные; рейтинг отсутствует у 9,3%, отзывы — у 6,1%; рейтинг почти всегда близок к 5. Повторные пары — 6,15% строк train.
- Выводы для поиска:
  - Поиск по содержанию объявления; ID и популярность как признаки не обобщаются.
  - Два канала: BM25 с морфологией для точных терминов и dense E5 для синонимов; объединение через RRF.
  - Город и категория — признаки, а не фильтры: глобальные кандидаты плюс кандидаты с тем же location_id.
  - Документ для E5: заголовок → ограниченные параметры → описание, чтобы уложиться в 512 токенов.
  - Короткие неоднозначные запросы: широкий пул кандидатов и отдельный отбор 50.
  - Валидация: split по нормализованным текстам, равный вес запросов, позитивы — множество по полному контексту; полнота пула и Recall@50 считаются раздельно.
- Файлы: `notebooks/eda.ipynb`, `pyproject.toml`, `uv.lock`, `.gitignore`, эта запись журнала. Добавлена отдельная группа зависимостей `eda`.
- Ограничения: почти все агрегаты считаются по полным файлам; лексическое пересечение — на 20 000 уникальных положительных пар с seed=42. Примеры выбраны намеренно, не являются оценкой частот ошибок. Это EDA, не качество обученного поиска; benchmark-меток нет. Значение цены −1 и иерархия локаций не документированы. Длину токенизированного текста предстоит проверить выбранным энкодером.
- Следующий шаг: зафиксировать split по нормализованным текстам запросов, реализовать macro Recall@50 и BM25 baseline.

## DEV-003 — Split, macro Recall@K и BM25 baseline

- Цель: воспроизводимая локальная валидация и первые измерения лексического канала.
- Результат: пакет `src/candgen`; команды `uv run python -m candgen.prepare_split` и `uv run python -m candgen.evaluate_bm25 [--title-repeat N] [--query-filters]`; отчёты — `data/artifacts/experiments/*.json`.
- Split:
  - Нормализация запроса: нижний регистр, `ё → е`, схлопывание пробелов.
  - Сплит определяется SHA-256 от `seed=42` и нормализованного текста: 80/10/10. Тексты: train 58 956, dev 7 458, test 7 459; пересечений нет.
  - Контекст — нормализованный текст + 4 поля `search_*`; позитивы — множество `item_id`. Контексты: 275 892 / 40 405 / 38 008.
  - `eval_dev`, `eval_test`: по 2 452 различных текста, один контекст на текст, выбор по seeded hash.
  - Локальный корпус — все 344 825 уникальных объявлений train, отсортированы по `item_id`.
- BM25: BM25S (lucene, k1=1.5, b=0.75), Snowball-стеммер PyStemmer `russian`, стоп-слова `ru`. Документ: заголовок ×N + параметры + описание. Ранги с равным score упорядочены по `item_id`; кандидаты с нулевым score отбрасываются.
- Метрики на dev (2 452 запроса, глобальная выдача, без локации):

  | Вариант | R@50 | R@100 | R@300 | R@1000 |
  |---|---:|---:|---:|---:|
  | заголовок ×1 | 0,3110 | 0,4051 | 0,5705 | 0,7529 |
  | заголовок ×3 | 0,3345 | 0,4243 | 0,5844 | 0,7685 |
  | ×1 + фильтры в запросе | 0,3148 | 0,4108 | 0,5823 | 0,7680 |
  | ×3 + фильтры в запросе | **0,3398** | 0,4288 | 0,5889 | 0,7764 |

- Срезы лучшего варианта (R@50): фильтры пусты 0,3912 (n=1 062), заданы 0,3005 (n=1 390); 1 слово 0,3127 (163), 2 — 0,3130 (882), 3 — 0,3703 (775), 4+ — 0,3468 (632); позитивы без взаимодействий в train-части 0,3536 (n=1 658). Категория 0 — n=2, вывода нет.
- Ресурсы: индекс 65–68 с, поиск top-1000 для 2 452 запросов ~11 с (30 потоков CPU), пиковая RSS 6,7 ГБ. `prepare_split` — 6 с, 5,1 ГБ.
- Находки: между R@50 и R@1000 разрыв 0,44 — нужные объявления часто находятся, но глубоко; усиление заголовка и фильтры дают +0,029 к R@50. Запросы с фильтрами хуже на 0,09.
- Лемматизация pymorphy3 вместо Snowball (×3 + фильтры): R@50 0,3423 против 0,3398, парный bootstrap 95% CI [−0,0034; +0,0084] — разница в пределах шума; индекс 104 с против 68 с. Оставлен Snowball.
- Ограничения: локация не используется; параметры k1/b не подбирались; вес заголовка через повтор текста — грубое приближение полевого BM25. Корпус 345k и доля пустых фильтров (43% dev против 63% benchmark) отличаются от бенчмарка.
- Артефакты перенесены в `data/artifacts/` (`ARTIFACTS_DIR` в `candgen.data`).
- Следующий шаг: dense-канал `multilingual-e5-base` (глобальная выдача на dev), затем гибрид BM25 + dense через RRF и уже на гибриде пул global + local по `item_location_id == search_location_id`.
- Соглашение по сабмитам: каждый ответ — отдельная папка `data/output/NNN_YYYYMMDD-HHMMSS_<tag>/` с `answer.csv` и `meta.json` (конфигурация, dev Recall@50, commit, SHA-256 файла). `NNN` — следующий порядковый номер, время — момент генерации; сортировка по имени совпадает с хронологией. Ранее созданные папки не перезаписываются.
