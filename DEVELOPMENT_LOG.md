## Как устроено решение

1. **BM25** ищет совпадения слов с русским стеммингом. Индексируется заголовок ×3, параметры и описание; фильтры добавляются к запросу.
2. **E5** ищет по смыслу. Используется `intfloat/multilingual-e5-base` без дообучения, ревизия `d128750`. Документ: заголовок, первые 500 символов параметров, описание; максимум 512 токенов.
3. Каждый канал возвращает до **250 глобальных + 200 локальных + 50 радиусных** кандидатов. Локальные объявления имеют тот же `location_id`, что и запрос; радиусные — ближе 25 км к центру локации запроса при любом `location_id` (EXP-003). Объединение содержит не более 1 000 объявлений, в среднем 670 на dev.
4. **CatBoostRanker** отбирает 50 объявлений по 35 признакам: рангам и score каналов, RRF, текстовому сходству, географии и свойствам объявления. RRF — сумма обратных рангов — служит простым вариантом для сравнения и источником признаков.
5. **Резервный центр локации (EXP-001 `a`).** Если в корпусе нет объявлений локации запроса, расстояние считается до медианы координат объявлений, которые исторически выбирали из этой локации. Модель дополнительно видит источник центра и объём истории.

Глобальный поиск сохраняется: одинаковый `location_id` не обязателен для релевантного объявления, а иерархия кодов неизвестна. Центр локации — это медиана координат объявлений, а не положение пользователя; исторический центр — медиана координат выбранных объявлений, тоже не положение пользователя.

## Ограничения

- **Dev отличается от benchmark:** корпус больше, пустые фильтры встречаются у 48% против 63%, категория `0` представлена одним запросом против 222. Значения на dev и платформе нельзя считать оценками одной и той же выборки.
- **Вклад географии измерен, но остаётся риск переноса.** Удаление расстояния стоит 1,50 п.п. (EXP-000 `no_dist`) при важности 45,8% — важность не равна приросту. Резервный центр по истории добавил 3,39 п.п. на dev и 3,02 п.п. на платформе. Центр строится по координатам **выбранных** объявлений, то есть по целевой информации: dev/test и группы ранней остановки в историю не входят, обучающие запросы получают историю чужих групп. У 94 из 427 benchmark-запросов без центра разброс истории больше 100 км — там признак близок к шуму.
- **Метки неполные:** невыбранное объявление может быть релевантным. У принятого варианта на dev 6,05 п.п. recall теряются до пула и 6,60 п.п. — при отборе 50. Это ориентир для экспериментов, не обещание достижимого прироста.
- **Документы E5 обрезаются:** около 35,5% проверенной выборки длиннее 512 токенов.
- **Оформление сдачи не завершено:** README содержит только название; `data/` исключён из Git. Проверяющему нужны инструкция запуска и компактные отчёты в репозитории.

### Общие правила сравнения

**Две точки отсчёта.** `B0` — сохранённый CatBoost из DEV-007: R@50 = **0,8396275**, полнота пула = **0,9395396**. `P` — последний принятый вариант. Каждый эксперимент сравнивать и с `P` для оценки отдельного изменения, и с `B0` для накопленного эффекта. Если эксперимент не принят, следующий начинается с прежнего `P`. Родителя и состав изменений записывать в отчёт.

**Неизменная оценка.** Сохранить текущие ID и позитивы 2 452 dev-запросов, корпус и нормализацию. Зафиксировать текстовые группы внутренней проверки для ранней остановки; они не должны меняться при увеличении train. Сохранять правила обучения и seed, пока именно они не являются предметом эксперимента. Оценочный пул никогда не пополнять известными позитивами. Считать все dev-запросы, включая случаи без найденных позитивов.

**Что измерять в каждом запуске:**

- Macro Recall@50 и его изменение относительно `P` и `B0`; парный bootstrap по одним и тем же запросам, 5 000 повторов, seed 42, CI95 для разности.
- Полноту всего фактического пула, его средний размер и p95, долю пустых пулов. Если вводится ограничение размера, отдельно считать полноту до и после ограничения. R@1000 не подменяет полноту пула больше 1 000.
- Качество на однословных запросах, с фильтрами и без них, с исходно отсутствующим центром локации, на новых объявлениях. Для географии дополнительно считать recall по позитивам с совпадающим и другим `location_id`, явно указывая знаменатель и число запросов/пар.
- Время подготовки и инференса, обучение, пиковую RAM/GPU. Различать холодный запуск и использование кэша. Для срезов с малым числом запросов не делать уверенных выводов по точечной оценке.

**Как принимать решение.** Убедительный кандидат — положительная разность общего R@50 с CI95 выше нуля, без существенного ухудшения важных срезов и неприемлемого роста ресурсов. Если интервал пересекает ноль, пометить результат как неопределённый и проверить устойчивость на нескольких seed; не объявлять улучшением. Ускорение без роста качества оценивать отдельно. Интервалы после множества проб не устраняют подбор по dev: окончательная независимая проверка — один раз на test после фиксации конфигурации.

**Артефакты.** Для каждого запуска — отдельный каталог, например `data/artifacts/experiments/EXP-001/a/`. Это предлагаемое соглашение, текущие скрипты ещё не обеспечивают такую изоляцию. Хранить конфигурацию, commit/dirty, версии входных данных и split, ID обучающих и проверочных групп, параметры истории, модель, оценки по каждому dev-запросу, отчёт, время и память. Для новых признаков и источников кандидатов расширить ключи кэша: совпадения только ID запросов недостаточно. Старые модели, отчёты и CSV не перезаписывать.

### Исторические признаки: защита от утечки

Это обязательная часть EXP-001, EXP-002 и EXP-006, а также кандидатов, использующих их статистики. Расстояние до медианы **выбранных** объявлений тоже использует целевую информацию и должно строиться по этим правилам.

1. Все строки текстов внешних dev/test исключить из истории, независимо от локации и фильтров. Все строки текстов внутренней проверки ранней остановки также исключить из истории, используемой при обучении и этой проверке.
2. Для обучающих примеров использовать перекрёстное построение признаков: разбить разрешённые train-тексты на пять фиксированных групп; признаки и исторически обусловленные кандидаты группы строить по остальным группам. Удалять весь нормализованный текст, а не одну пару или один контекст. Оставшиеся train-тексты вне выборки модели могут входить в историю при соблюдении этих исключений.
3. Для внутренней проверки использовать разрешённую train-историю без её текстов. Для внешнего dev/test также не добавлять их метки в историю. В первой серии сохранить один и тот же состав разрешённой истории для внешней оценки, чтобы сравнения не смешивались с её расширением.
4. Для benchmark допустима полная предоставленная train-история. Переход от частичной к полной истории зафиксировать в конфигурации; использовать те же формулы и обработку неизвестных значений. Скрытая разметка benchmark не используется.
5. Для редких и неизвестных групп предусмотреть сглаживание, признаки поддержки и пропуска. Основные счётчики начать с уникальных пар «полный контекст — item_id»; влияние повторных взаимодействий проверять отдельным вариантом.

Проверки реализации: пересечения текстов отсутствуют; изменение меток отложенной группы не меняет её исторические признаки или кандидатов; неизвестная локация/микрокатегория обрабатывается без ошибки; метки dev/test применяются только для расчёта метрик. Если реализация перекрёстных признаков слишком сложна для первого запуска, можно выделить отдельную непересекающуюся часть train под историю, но такой протокол нужно зафиксировать и не смешивать с перекрёстным в одной таблице сравнений.

### EXP-000 — База сравнения и карта ошибок

**Гипотеза:** сначала нужно понять, какие ошибки лежат в поиске, а какие — в отборе, и обеспечить повторяемое сравнение.

**Действия:** сохранить модель, конфигурацию, текущие пулы, top-50 и recall каждого dev-запроса для `B0`; подтвердить R@50 = 0,8396275 и полноту 0,9395396. Зафиксировать группы ранней остановки до изменения размера обучения. Составить таблицу ошибок: нет позитива в пуле; позитив есть, но ниже 50; ошибка географии; неоднозначный текст; недостаток совпадения фильтров. Ручные примеры выбирать для объяснения, частоты считать по всей выборке.

**Диагностический вариант:** переобучить ту же модель без расстояния на том же пуле. Это проверяет вклад признака; 45,8% важности CatBoost само по себе не равно доле прироста качества. Удалять расстояние из основной модели по одному лишь значению важности не нужно.

**Готовность:** воспроизводятся исходные метрики, сохранены результаты по запросам и размеры срезов, определена версия протокола. Без этого не переходить к сравнению новых моделей. Эмбеддинги и поиск заново считать не требуется, если проверена пригодность кэша.

**Результат `b0`.** Статус: выполнен. Модель DEV-007 применена к кэшированным dev-выдачам командой `experiment --exp EXP-000 --variant b0 --model …`: R@50 = **0,8396275**, полнота пула = **0,9395396**, пул 735 в среднем, p95 893, пустых нет — совпадает с DEV-007. Протокол `v1`: результаты по запросам и позитивам в `data/artifacts/experiments/EXP-000/b0/`; группы ранней остановки зафиксированы в `data/artifacts/split/ranker_valid_texts.parquet` (правило DEV-007 на выборке 6 000 текстов).

### EXP-001 — Резервный центр локации из истории выборов

**Гипотеза:** для запросов без центра по объявлениям их локации полезен ориентир по координатам исторически выбранных исполнителей.

**Изменение:** на разрешённой истории сгруппировать выбранные объявления по `search_location_id`; рассчитать медианы широты/долготы, число уникальных пар и объявлений, медианное расстояние выбранных объявлений до полученного центра. Не называть этот центр положением пользователя. При недостатке данных или большом разбросе оставлять явный сигнал низкой надёжности.

### EXP-002 — Вероятности переходов между локациями

**Гипотеза:** история переходов учитывает соседние районы и выездные услуги, которые не описываются равенством ID и одним расстоянием.

**Изменение:** построить счётчики `C(s, l)` выборов локации объявления `l` из локации поиска `s`. Начать с распределения, сглаженного к доле объявлений локации в доступном корпусе:

```text
p_corpus(l) = число объявлений локации l / размер корпуса
p(l | s) = (C(s, l) + alpha * p_corpus(l)) / (C(s) + alpha)
geo_lift(s, l) = log(1 + p(l | s) / p_corpus(l))
```

Здесь `alpha` — сила сглаживания. Для этой версии считать `C(s)` по целевым локациям, представленным в корпусе, и отдельно сохранять долю исторических переходов за пределы корпуса. Без истории распределение возвращается к корпусному; поддержку передавать отдельным признаком. В первой серии проверить не более двух заранее записанных значений `alpha`, например 10 и 100, на внутренней проверке.

**Признаки:** `p(l | s)`, `geo_lift`, число переходов пары, общая поддержка исходной локации, разнообразие направлений и флаг неизвестной пары. Координаты для этих признаков не обязательны.

**Сравнение:** родитель после EXP-001, неизменный пул и обучение. Сначала проверить вероятность с поддержкой, затем дополнительный эффект lift и разнообразия. Не добавлять одновременно новый географический канал поиска.

**Решение:** проверить общий R@50, исходно отсутствующий центр, несовпадающие локации и редкую историю. Убедиться, что популярные локации не вытесняют релевантные объявления других направлений. При отсутствии выигрыша оставить прежнего родителя; к географическому поиску можно перейти как к отдельной проверке полезности сигнала для полноты.

**Затраты:** статистики, признаки и CatBoost; без пересчёта эмбеддингов.

**Реализация, не измерено.** `experiment --transitions prob|full --transition-alpha A` на той же истории и тех же группах cross-fit, что EXP-001. `prob`: `trans_prob`, `trans_pairs`, `trans_support`, `trans_unknown`; `full` добавляет `trans_lift`, `trans_targets`, `trans_outside_share`. Для split-корпуса доля переходов за пределы корпуса всегда 0: корпус состоит из всех объявлений train.

### EXP-003 — География на этапе поиска кандидатов

**Гипотеза:** географический сигнал должен помогать находить объявления до CatBoost, поскольку модель не вернёт позитив, отсутствующий в пуле.

**Изменение:** добавить отдельные BM25/dense-списки с мягкой поправкой на расстояние и/или вероятность перехода. Глобальные списки сохранить. Не применять жёсткое исключение остальных локаций. Масштаб поправки подбирать отдельно для лексического score и сходства E5; чужие коэффициенты не переносить без проверки.

**Чистое сравнение бюджета:** у каждого канала сравнить нынешние `300 global + 200 local` с `250 global + 200 local + 50 soft-geo`: суммарный предел до дедупликации остаётся 1 000. Сохранить также результат `250 global + 200 local` без нового списка, чтобы видеть вклад добавленных кандидатов. Если есть перспективный эффект, отдельно проверить расширение бюджета; не смешивать его с первым сравнением.

**Проверки:** полнота всего пула, уникальные позитивы нового канала, размер и время поиска. Затем переобучить CatBoost на новых train-пулах и оценить финальный R@50. Для train исторические поправки и сами пулы строить без собственной текстовой группы по общему протоколу.

**Решение:** не принимать канал лишь за рост полноты, если после переобучения ухудшается top-50. Если полнота выросла, а отбор нет, сохранить результат как отдельную гипотезу об отборе, не заменяя победителя.

**Затраты:** новые выдачи и признаки; E5-векторы документов и неизменных запросов переиспользуются. Кэш должен различать историю, поправку и глубины списков.

### EXP-004 — Отдельные текстовые оценки и соответствие фильтров

**Гипотеза:** общий BM25-score скрывает разницу между совпадением в заголовке, описании и параметрах; отдельный сигнал фильтров поможет отличать похожие услуги.

**Изменение:** для каждого кандидата текущего пула рассчитать BM25 отдельно по заголовку, описанию и параметрам, а также соответствие `search_infm_params_text` параметрам объявления. Для пустых фильтров — нулевой score и отдельный флаг. Общий BM25 и нынешние признаки оставить.

**Варианты:** `a` — три полевые оценки; `b` — добавить оценку фильтров; `c` — при наличии выигрыша проверить нормированное по IDF покрытие слов и совпадение фразы. Нормализацию и обрезку полей сначала оставить прежними, чтобы не менять несколько факторов сразу. Оценки считать для всех кандидатов, включая найденных только dense-каналом.

**Сравнение:** неизменный пул, одинаковое обучение. Сначала признаки, затем отдельным экспериментом — возможное использование полевых индексов для новых кандидатов. Основные срезы: заданные фильтры, короткие запросы, объявления с одинаковыми заголовками.

**Решение:** принять только подтверждённый прирост, а не высокую важность новых признаков. Отсутствие слова не трактовать как доказательство нерелевантности.

**Затраты:** лексические индексы/оценки, признаки, CatBoost; без новых E5-эмбеддингов.

**Реализация, не измерено.** `experiment --field-scores fields|filters` (`core/fields.py`). Три отдельных BM25-индекса (`k1=1.5`, `b=0.75`, стемминг и стоп-слова как у основного канала) по нормализованным заголовку, полным параметрам и описанию. `fields` добавляет `bm25_title`, `bm25_params`, `bm25_description` — оценки запроса без фильтров; `filters` добавляет `bm25_filters` — оценку текста фильтров по индексу параметров, 0 при пустых фильтрах. Оценки считаются для всех кандидатов пула, включая найденных только E5 и радиусом; пул не меняется.

Исправлено до первого запуска: неизвестное индексу слово токенизатор отображает в пустой токен, а пустой токен есть у всех объявлений с пустым полем — такие объявления получали положительную оценку. Для полевых оценок пустой токен из запроса удаляется. Основной BM25 не затронут: пустых документов в обоих корпусах нет (проверено).

Предварительно, на dev-пуле `r25x50` без обучения: медианная относительная позиция позитива внутри пула по признаку — заголовок 0,24, описание 0,22, фильтры 0,40 (запросы с фильтрами), параметры 0,48; 0,5 соответствует случайному порядку. Построение индексов 67 с, оценки dev 3 с.

**Результат.** Статус: `fields` — неопределённый, `filters` — хуже. Родитель `fields` — EXP-003 `r25x50`, родитель `filters` — `fields`; коммит `344b26f`, чистое дерево.

### EXP-005 — Символьное сходство для опечаток и названий

**Гипотеза:** символьные 3–4-граммы заголовка дополняют стемминг на опечатках и вариантах написания.

**Изменение:** построить TF-IDF по символьным n-граммам заголовков и добавить косинусное сходство запроса с заголовком для каждого кандидата. Индекс и нормализацию фиксировать в метаданных. Сначала не добавлять новые объявления в пул.

**Сравнение:** родитель после EXP-004, прежний пул и настройки модели. Рассмотреть примеры с опечатками и названиями; ручной набор использовать как диагностику, не как замену всему dev и не как повод подгонять частные правила.

**Второй шаг:** если такие позитивы отсутствуют в пуле, проверить отдельный небольшой символьный список, например top-50, с явным перераспределением прежнего бюджета. Переобучить отбор. Не объединять эффект нового признака и нового списка в одну оценку.

**Решение:** общий R@50 и дополнительная полнота должны оправдывать память индекса и время поиска. Если улучшения нет, не оставлять канал только ради разнообразия методов.

### EXP-006 — Микрокатегории из похожих обучающих запросов

**Гипотеза:** широкая категория мало различает услуги; распределение микрокатегорий по похожим запросам помогает уточнить намерение пользователя.

**Изменение:** индексировать нормализованные тексты разрешённой истории по словам и символам. Для нового запроса искать до 40 похожих текстов и получать взвешенное распределение их выбранных `item_microcat_id`. Историю каждого текста нормировать, чтобы частый текст не доминировал одним количеством строк. Слабых соседей отбрасывать; при их отсутствии возвращать явный пропуск/флаг, а не произвольную категорию.

**Признаки:** вероятность микрокатегории кандидата, её отношение к максимальной вероятности, неопределённость распределения, сходство ближайшего запроса и поддержка. Сначала без популярности `item_id` и прямого сигнала совместных выборов: так проще проверить перенос на новые объявления.

**Сравнение:** неизменный пул и модель родителя; меняются только признаки. Для обучающего текста его собственные варианты в других локациях и фильтрах также исключаются из истории. Основные срезы — однословные запросы, разные услуги с похожим названием и новые объявления.

**Второй шаг:** только после отдельной проверки признаков рассмотреть кандидатов с мягким приоритетом микрокатегорий. Не делать жёсткий фильтр: у неоднозначного запроса может быть несколько подходящих категорий.

**Затраты:** индекс истории, признаки и обучение. Новые эмбеддинги объявлений не нужны. Пользу запоминания конкретных объявлений не смешивать с пользой микрокатегорий.

**Реализация, не измерено.** `experiment --microcats neighbors` (`core/microcats.py`). Похожесть текстов — E5 без дообучения, `query: ` + нормализованный текст без фильтров; векторы исторических текстов кэшируются в `data/artifacts/runs/history/`. Для каждого текста истории — доли микрокатегорий выбранных объявлений, каждый текст весит одинаково независимо от числа строк. Для запроса берутся 40 ближайших разрешённых текстов с весами `exp((sim − sim_max) / 0,05)`: слабые соседи получают малый вес. Признаки кандидата: `mc_prob` — вероятность его микрокатегории (0, если её нет у соседей), `mc_ratio` — отношение к максимальной вероятности, `mc_entropy` — неопределённость распределения, `mc_top_sim` — сходство с ближайшим текстом. Разрешённые тексты — те же представления истории, что у EXP-001: cross-fit по пяти группам для train, вся разрешённая история для внутренней проверки и dev, вся train-история для benchmark. Свой текст обучающего запроса и dev-тексты в соседи не попадают.

Ограничение переноса: на benchmark 907 из 2 452 текстов есть в train, и ближайшим соседом станет сам текст (`mc_top_sim` ≈ 1). В обучении и на dev такого случая нет по построению split. Распределение точного текста должно быть точнее соседского, но dev этот эффект не измеряет.

### EXP-007 — Меньше негативов на запрос

**Гипотеза:** часть объявлений обучающего пула избыточна; разумная выборка негативов снизит стоимость обучения и позволит охватить больше текстов.

**Изменение:** оставить все позитивы, уже найденные в обучающем пуле. Из остальных кандидатов собрать трудные негативы из верхних позиций каналов/RRF и дополнить случайными. Как стартовый бюджет — до 150 трудных и 50 случайных уникальных негативов на запрос; зафиксировать seed и состав выборки. Позитивы, не найденные поиском, в первой версии искусственно не добавлять.

**Сравнение:** те же обучающие запросы и признаки, тот же CatBoostRanker и функция потерь. На dev/test и при инференсе ранжировать полный обычный пул. Не менять одновременно веса классов или модель на классификатор.

**Решение:** сравнить качество, RAM и время с обучением на полном пуле. Для принятия именно как ускорения заранее задать допустимую потерю R@50, например 0,002, и проверить нижнюю границу CI95 разности относительно этого порога. Потерю качества не называть улучшением. Если экономия мала или качество заметно ухудшается, оставить полный пул.

**Ограничение:** ненаблюдавшиеся пары — приближённые негативы; самые трудные из них могут быть релевантны. Не использовать dev-метки для выбора негативов.

### EXP-008 — Больше текстов и устойчивая настройка CatBoost

**Гипотеза:** текущих 5 093 обучающих групп недостаточно для устойчивого использования новых признаков, а ранняя остановка по 530 запросам может быть шумной.

**Последовательность:**

1. При зафиксированных признаках, пуле и способе выбора негативов увеличить число выбранных train-текстов с 6 000 до 15 000. Группы внутренней проверки не менять и не включать их в обучение или историю. Сохранять отдельные числа: сколько текстов выбрано, сколько реально обучает модель, сколько не имеет позитивов в пуле.
2. Если затраты и качество оправданы, проверить 30 000 текстов. Если меняется состав истории, сначала отделить этот эффект от увеличения обучающей выборки; предпочтительно сохранять прежние правила и базу истории.
3. На выбранном размере последовательно проверить глубины 4/6/8 при прежнем `learning_rate`, затем две скорости обучения при выбранной глубине. Не начинать с большой полной сетки. Число деревьев выбирать только на внутренней проверке.
4. Для лучшего варианта проверить несколько seed, например 42/43/44, на неизменных разбиениях. Отдельно сообщить разброс R@50 и числа деревьев; не выбирать seed по платформе.

**Шаг 4: seed.** Статус: выполнен. `v2_base` с seed 43 и 44 при тех же данных, пуле и 500 деревьях, коммит `33f2314` (у `v2_seed44` дерево помечено изменённым: правки EXP-006 внесены после старта и в запуск с `--microcats none` не входят).

| seed | R@50 | К seed 42, п.п. [CI95] | Потери при отборе, п.п. |
| --- | ---: | --- | ---: |
| 42 (`v2_base`) | 0,8888 | — | 7,30 |
| 43 | 0,8896 | +0,08 [−0,31; +0,47] | 7,22 |
| 44 | 0,8906 | +0,18 [−0,22; +0,59] | 7,12 |

Среднее 0,8897, **стандартное отклонение по seed 0,09 п.п.**, размах 0,18 п.п. Шум обучения в протоколе `v2` в несколько раз меньше интервала bootstrap по запросам (±0,4–0,5 п.п.): основная неопределённость — конечная dev-выборка, а не случайность модели. Разность больше ~0,3 п.п. при одном seed уже не объясняется выбором seed, но может объясняться составом запросов.

Усреднение предсказаний трёх seed на dev (нормированные score): 0,8900, к seed 42 +0,12 [−0,18; +0,43] — на уровне среднего по seed, ансамбль отдельного выигрыша не даёт.

### EXP-009 — Расширение существующего пула

**Гипотеза:** более глубокие списки дадут дополнительные позитивы, которые улучшенный CatBoost сможет отобрать.

**Изменение:** сравнить глубины `300 global + 200 local` и `500 global + 300 local` на канал. Если к этому моменту приняты новые каналы, их квоты оставить одинаковыми в обеих конфигурациях и пересчитать полный бюджет. Предварительные 0,9546 получены для исходных четырёх списков, а не для будущей расширенной архитектуры.

**Сравнение:** одинаковые признаки, train-тексты, настройки и правила семплирования; модель переобучить для каждого пула. Не считать применение старого CatBoost к новому пулу окончательной проверкой. Сохранить исходные списки, порядок и ID запросов, чтобы исключить несовместимый кэш.

**Решение:** прирост полного пула должен переходить в R@50. Сравнить p95 размера пула и время инференса. Лимит 1 000 был внутренним бюджетом, а не ограничением платформы; итоговый CSV всегда содержит не более 50 ID. При ограничении нового пула отдельно оценить потери от этого ограничения.

**Затраты:** при наличии совместимых кэшей global 1 000/local 500 повторный поиск не нужен; нужны новые признаки и обучение. Для новых каналов кэш может потребовать расширения.

**Полнота пула при радиусных списках** (dev, готовые выдачи, без обучения):

| Global + local + radius 25 км на канал | Полнота пула | Средний пул | p95 |
| --- | ---: | ---: | ---: |
| 250 + 200 + 50 (`v2_base`) | 0,9618 | 670 | 815 |
| 300 + 200 + 50 | 0,9626 | 750 | 904 |
| 400 + 300 + 50 | 0,9680 | 1 016 | 1 246 |
| 400 + 300 + 100 | 0,9714 | 1 037 | 1 264 |
| 500 + 300 + 100 | 0,9742 | 1 194 | 1 443 |
| 600 + 400 + 100 | 0,9785 | 1 451 | 1 776 |

Прирост 400 + 300 + 50 (+0,62 п.п.) равен приросту `r50x100_v2`, который отбор не удержал (−0,56 п.п. R@50). Ожидаемая польза EXP-009 ниже, чем предполагалось: запуск имеет смысл только поверх признаков, улучшающих отбор (EXP-006), и с учётом роста обучающей таблицы в 1,5 раза.

### EXP-010 — Представление текстов для E5

**Гипотеза:** текстовые фильтры могут мешать семантике короткого запроса, а обрезка документа — терять полезное описание. Проверять эти причины раздельно и после более дешёвых сигналов.

**Вариант `a`: запрос без фильтров.** Сохранить E5-base, ревизию и документы. Пересчитать только векторы запросов, dense-выдачи и зависящие от них признаки; переобучить CatBoost. Фильтры остаются в отдельных лексических признаках. У RRF разница ранее была статистически неопределённой; это не доказывает такой же результат с новым отбором. Совместимый кэш запросов без фильтров можно переиспользовать после проверки.

**Вариант `b`: больше параметров документа.** Отдельно сравнить лимиты 500 и 1 000 символов при прежних 512 токенах. Измерить, не вытесняют ли параметры полезное описание. Потребуется пересчёт эмбеддингов локального корпуса, выдач, признаков и модели. Benchmark-корпус пересчитывать только для выбранного кандидата.

**Вариант `c`: несколько фрагментов.** Ставить, если анализ связывает промахи с обрезкой текста. Начать с исходного представления плюс одного дополнительного фрагмента описания; объединять фрагменты по `item_id` до ограничения пула и оценки. Для каждой конфигурации сохранять число фрагментов, правило агрегации и объём индекса. Не заявлять, что два фрагмента покрывают весь документ.

**Решение:** измерить общий R@50, полноту, длинные документы, стоимость индекса и поиска. Сначала принять или отклонить `a`, затем отдельно `b`/`c`; не запускать все изменения одновременно. Замена E5-base на E5-small не является обязательной: чужая метрика не изолирует влияние размера модели.

### EXP-011 — Альтернативное обучение, только при оставшемся резерве

**Гипотеза:** после фиксации сильных признаков другой способ обучения может улучшить отбор, но это не следует из самого факта использования Classifier в другом проекте.

**Изменение:** сравнить CatBoostRanker и CatBoostClassifier на одних кандидатах, признаках и текстовых группах. Для классификатора отдельно проверить невзвешенный вариант и нормирование суммарного веса позитивов на запрос. Коэффициент позитивного класса выбирать на внутренней проверке, а не автоматически переносить из чужого кода. Число деревьев выбирать по внешнему для модели расчёту macro Recall@50 на внутренней проверке.

**Сравнение:** одинаковый бюджет настройки; полный пул при оценке. Формулировать результат как сравнение двух способов обучения, а не вывод о превосходстве библиотеки или количестве деревьев. Если различие в пределах шума, сохранить более простой уже проверенный вариант.

**Отдельная поздняя гипотеза:** добавление ненайденных позитивов только в обучающий пул. Не объединять с заменой модели; обеспечить расчёт всех признаков для таких объявлений. На dev/test/benchmark ничего по меткам в пул не добавлять, полноту считать до любых обучающих добавлений.

### Форма результата и завершение серии

Для каждого `EXP-*` добавить короткую запись после выполнения:

```text
Статус: выполнен / принят / отклонён / результат неопределённый.
Родитель: ID эксперимента, commit, конфигурация.
Изменение: один проверяемый фактор; что зафиксировано.
Данные: версия split, fit/valid/dev, правило истории и выборки негативов.
Качество: R@50, разность и CI95 к родителю и B0, полнота и размер пула.
Срезы: выигрыш/регрессия с числом запросов; примеры ошибок отдельно.
Ресурсы: время, RAM/GPU, какие кэши использованы.
Артефакты: отчёт, модель, предсказания по запросам, конфигурация.
Решение: обоснование и родитель следующего эксперимента.
```

Независимый test открыть один раз после выбора финальной конфигурации; не использовать результат для очередного подбора. На платформу отправлять только отобранные варианты и для каждой фактической отправки записывать точный файл, SHA-256, конфигурацию и метрику. Количество оставшихся попыток уточнять по фактическим отправкам, а не по числу локальных CSV. Параллельно дополнить README, сохранить компактные отчёты вне `data/` и проверить воспроизведение итогового ответа.
